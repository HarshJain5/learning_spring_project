# Why Project Structure Matters?

A Spring Boot project follows a standard structure.

Benefits:

- Easy to understand
- Easy to maintain
- Easy to scale
- Every developer knows where to find code

A well-organized project is easier to debug and extend.

---

# resources Folder

```
src/main/resources
```

Contains non-Java files.

Examples:

- application.yml

Current project:

```
resources
│
└── application.properties
```

# application.properties

This file stores application configuration.

Examples:

```properties
server.port=8080
```

```properties
spring.datasource.url=...
```

```properties
spring.datasource.username=...
```

```properties
spring.datasource.password=...
```

Instead of hardcoding configuration in Java, Spring Boot reads it from this file.

# pom.xml

```
pom.xml
```

One of the most important files.

POM = **Project Object Model**

It tells Maven:

- Project name
- Java version
- Dependencies
- Plugins
- Build information

Example:

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>
```

Without `pom.xml`, Maven cannot build the project.

---

# target Folder

```
target/
```

Created automatically after building the project.

Contains:

- Compiled classes
- Generated JAR
- Build files

Example:

```
target
│
├── classes
├── generated-sources
└── first-spring-proj-0.0.1-SNAPSHOT.jar
```

Do **not** edit files inside `target`.

It can be safely deleted because Maven recreates it.

---

# .mvn Folder

```
.mvn/
```

Contains Maven Wrapper configuration.

Usually, you don't need to modify it.

---

# mvnw

```
mvnw
```

Maven Wrapper for Linux/macOS.

Allows running Maven without installing Maven globally.

Example:

```bash
./mvnw clean install
```

# mvnw.cmd

Windows version of Maven Wrapper.

Example:


# Main Application Class

Example:

```java
@SpringBootApplication
public class FirstSpringProjApplication {

    public static void main(String[] args) {
        SpringApplication.run(
            FirstSpringProjApplication.class,
            args
        );
    }

}
```

This is the entry point of the application.

When you click **Run**, execution starts here.

---

# @SpringBootApplication

This is the most important annotation.

It combines three annotations:

```
@SpringBootConfiguration

+

@EnableAutoConfiguration

+

@ComponentScan
```

We'll study each one later.

For now, remember:

It tells Spring Boot to start the application.

---

# SpringApplication.run()

```java
SpringApplication.run(...)
```

Responsibilities:

- Starts Spring Boot
- Creates Spring Container
- Creates Beans
- Starts Embedded Tomcat
- Opens Port 8080
- Makes application ready

# Why Keep Everything Under One Base Package?

Spring Boot scans components starting from the package containing the main application class.

Good:

```
com.spring.first_spring_proj

    ├── controllers
    ├── service
    ├── repository
```

Bad:

```
controllers

service

repository
```

outside the base package.

Spring may not detect them automatically.

# Request Flow

```

        │

        ▼

Controller

        │

        ▼

Service

        │

        ▼

Repository

        │

        ▼

Database

        │

        ▼

Response
```

Each package has one responsibility.

# Folder Responsibility

| Folder | Purpose |
|---------|---------|
| controllers | Handles HTTP requests |
| service | Business Logic |
| repository | Database Communication |
| entities | Database Tables |
| exceptions | Custom Exceptions |
| resources | Configuration Files |
| test | Unit Testing |

# Common Mistakes

❌ Creating `Controller` outside the base package.

❌ Writing database configuration inside Java code instead of `application.properties`.

❌ Editing files inside `target`.

❌ Adding Java classes inside `resources`.

❌ Deleting `pom.xml`.

# Interview Questions

### What is `src/main/java`?

Contains all Java source code.

---

### What is `resources` used for?

Stores configuration files, properties, templates, and static resources.

---

### What is `pom.xml`?

The Maven configuration file used to manage dependencies, plugins, and project settings.

---

### What is the `target` folder?

A build output folder containing compiled classes and generated artifacts.

---

### Where should Controllers be placed?

Inside the base package, typically in a `controllers` package.

---

### What is the purpose of `@SpringBootApplication`?

It marks the main class and enables auto-configuration, component scanning, and Spring Boot configuration.
